# 04. 정규 표현식

> 정규 표현식(regex)은 문자열에서 특정 패턴을 찾거나, 형식을 검증하거나, 패턴을 기준으로 나눌 때 쓰는 작은 언어다.

## 핵심 요약

- 간단한 규칙 하나로 시작해 조금씩 조건을 늘려 가며 만든다. <https://regex101.com/> 같은 도구에 실제 문자열을 넣고 확인하면서 작성한다.
- 파이썬에서는 패턴을 **raw 문자열**(`r"..."`)로 써서 역슬래시를 한 번만 쓴다.
- 입력값 전체의 형식을 검증할 때는 `re.search()` 가 아니라 **`re.fullmatch()`** 를 쓴다. `search` 는 일부만 맞아도 통과시킨다.
- 정규식은 느릴 수 있고, 잘못 만든 패턴은 서비스를 멈추게 할 수도 있다(**ReDoS**). HTML·JSON처럼 구조가 있는 문서는 정규식 대신 전용 파서를 쓴다.

## 기본 문법

### 문자 1개 찾기

| 패턴 | 의미 |
| --- | --- |
| `[a-z]`, `[A-Z]`, `[a-zA-Z]` | 소문자 / 대문자 / 영문자 1개 |
| `[0-9]` | 숫자 1개 |
| `[a-zA-Z0-9]` | 영문자 또는 숫자 1개 |
| `[^A-Z]` | 대문자가 **아닌** 문자 1개(대괄호 안 맨 앞의 `^` 는 부정) |
| `.` | 줄바꿈을 제외한 모든 문자 1개 |
| `\d`, `\D` | 숫자 / 숫자가 아닌 문자 |
| `\w`, `\W` | 단어 문자(영문자, 숫자, `_`, 한글 등) / 그 외(공백, 특수 문자) |
| `\s`, `\S` | 공백 문자(스페이스, 탭, 줄바꿈) / 그 외 |

- 대괄호 `[]` 는 "이 중 한 글자"를 뜻한다. 대괄호 안에서는 `.`, `$` 같은 문자가 특별한 의미를 잃고 그 문자 자체를 뜻한다.

### 위치

| 패턴 | 의미 | 예 |
| --- | --- | --- |
| `^` | 문자열의 시작 | `^[A-Z]`: 대문자로 시작 |
| `$` | 문자열의 끝 | `[0-9]$`: 숫자로 끝남 |
| `\b` | 단어 경계 | `\bcat\b`: `cat` 은 찾고 `category` 는 찾지 않음 |

### 반복

| 패턴 | 의미 |
| --- | --- |
| `*` | 0개 이상 |
| `+` | 1개 이상 |
| `?` | 0개 또는 1개 |
| `{3}` | 정확히 3개 |
| `{3,5}` | 3개 이상 5개 이하 |
| `{3,}` | 3개 이상 |
| `{,5}` | 5개 이하(파이썬에서 지원, 엔진마다 다름) |

- `[a-z0-9,]{3}` 는 "소문자, 숫자, 쉼표 중 하나가 연속으로 3개"를 뜻한다.
- 반복은 기본적으로 **가능한 한 길게(greedy)** 일치한다. `<.+>` 는 `<a><b>` 전체와 일치한다. 가장 짧게 일치시키려면 `<.+?>` 처럼 `?` 를 붙인다.

### 그룹

- 괄호 `( )` 로 묶으면 그 부분을 따로 꺼낼 수 있다. `(?P<name>...)` 로 이름을 붙일 수도 있다.

```python
m = re.fullmatch(r"(?P<user>[^@]+)@(?P<domain>.+)", "gigone.lee@gmail.com")
print(m["user"], m["domain"])  # gigone.lee gmail.com
```

## 특수 문자와 이스케이프

- `[`, `]`, `.`, `*`, `+`, `?`, `(`, `)`, `{`, `}`, `^`, `$`, `|`, `\` 는 정규식에서 특별한 의미가 있다. 문자 그대로 찾으려면 앞에 `\` 를 붙여 **이스케이프** 한다.
- 일반 문자열 안에서는 프로그래밍 언어와 정규식이 각각 역슬래시를 한 번씩 해석하므로 두 번 써야 한다. raw 문자열을 쓰면 정규식에 그대로 전달된다.

| 찾을 문자 | 일반 문자열 | raw 문자열 |
| --- | --- | --- |
| `[` 또는 `]` | `"[\\[\\]]"` | `r"[\[\]]"` |
| `\` | `"[\\\\]"` | `r"[\\]"` |

## 파이썬 `re` 함수

| 함수 | 동작 | 용도 |
| --- | --- | --- |
| `re.search(p, s)` | 처음 일치하는 곳 하나를 찾으면 멈춤 | 포함 여부 확인 |
| `re.fullmatch(p, s)` | 문자열 **전체** 가 패턴과 일치하는지 확인 | 입력 형식 검증 |
| `re.findall(p, s)` | 일치하는 모든 부분을 리스트로 반환 | 추출 |
| `re.split(p, s)` | 일치하는 곳을 기준으로 나눔 | 구분자 분리 |
| `re.sub(p, r, s)` | 일치하는 부분을 바꿈 | 치환, 마스킹 |
| `re.compile(p)` | 패턴을 미리 컴파일 | 같은 패턴을 반복해서 쓸 때 |

## 실사용 예

### 비밀번호 규칙 검증

- 조건마다 패턴을 따로 검사하면 읽기 쉽고, 어떤 조건이 빠졌는지 사용자에게 정확히 알려줄 수 있다. 여기서는 일치 여부만 필요하므로 `re.search()` 가 적절하다.

```python
rules = [
    (r".{8,}", "최소 8글자 이상이어야 합니다."),
    (r"[a-z]", "최소 1개 이상의 소문자가 필요합니다."),
    (r"[A-Z]", "최소 1개 이상의 대문자가 필요합니다."),
    (r"[0-9]", "최소 1개 이상의 숫자가 필요합니다."),
    (r"[@#$%^&+=]", "최소 1개의 특수 문자(@#$%^&+=)가 필요합니다."),
]
for pattern, message in rules:
    if not re.search(pattern, password):
        print(message)
```

### 구분자로 나누기

- `re.split("@", "gigone.lee@gmail.com")` 은 `['gigone.lee', 'gmail.com']` 을 돌려준다. 하이픈으로 전화번호를 나누는 것처럼 구분자가 여러 종류일 때(`r"[-. ]"`) 특히 편하다.

### 이메일 주소 검증

- 이메일 표준(RFC 5322)은 매우 많은 형식을 허용해서, 이를 그대로 옮긴 정규식은 수백 글자가 되고 아무도 고칠 수 없게 된다.
- 실무에서는 `^[^@\s]+@[^@\s]+\.[^@\s]+$` 정도로 기본 형식만 확인하고, **인증 메일을 보내** 실제로 받을 수 있는 주소인지 확인한다.

## 성능과 보안

- 정규식 엔진은 일치하는 경우를 찾기 위해 되돌아가며(backtracking) 여러 경우를 시도한다. 그래서 큰 문자열에 많은 패턴을 적용하면 느려진다.
  - 웹 요청이나 API처럼 응답 시간이 정해진 곳에서 큰 HTML·JSON 본문을 정규식으로 훑으면 서버 전체가 느려질 수 있다.
  - 크롤러처럼 구조가 있는 문서에서 정보를 꺼낼 때는 HTML 파서(`lxml`, `BeautifulSoup`)를 쓴다.
- `(a+)+$` 처럼 반복이 중첩된 패턴은 특정 입력에서 처리 시간이 기하급수적으로 늘어난다. 공격자가 이런 입력을 보내 서버를 멈추게 하는 것을 **ReDoS** 라고 한다.

> **주의** 사용자 입력을 정규식 패턴으로 그대로 쓰지 않는다. 꼭 써야 한다면 `re.escape()` 로 이스케이프하고, 입력 길이를 제한한다.

## 더 알아보기

- 정규식 문법은 POSIX, PCRE(펄 호환) 등 엔진마다 조금씩 다르다. 처음 쓰는 언어나 도구에서는 어떤 문법을 따르는지 확인한다.
- 비밀번호 정책: 미국 NIST(SP 800-63B)는 문자 조합 강제보다 **충분한 길이** 와 유출된 비밀번호 차단을 권장한다.
- 파이썬 3.11부터 원자 그룹(`(?>...)`)과 소유 수량자(`*+`, `++`)를 지원해 되돌아가기를 줄일 수 있다.
