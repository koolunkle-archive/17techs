# 07. 해시 함수

> 해시 함수는 데이터를 고정된 길이의 "지문"으로 바꾼다. 비밀번호 저장, 파일 무결성 검사, 해시 테이블처럼 성능과 보안 양쪽에서 두루 쓰인다.

## 핵심 요약

- 해시 함수는 어떤 길이의 입력이든 **고정된 길이의 해시 값** 으로 바꾼다. 입력이 같으면 결과도 같고, 해시 값에서 원래 입력을 되돌릴 수 없다.
- 보안 용도에는 **SHA-256 이상**(SHA-2, SHA-3)을 쓴다. MD5와 SHA-1은 충돌을 만들 수 있으므로 보안 용도로 쓰지 않는다.
- **비밀번호는 일반 해시 함수로 저장하지 않는다.** 일부러 느리게 설계된 **Argon2id, bcrypt, scrypt, PBKDF2** 를 쓰고, 사용자마다 무작위 **솔트** 를 붙인다.
- 해시 테이블, 중복 검사처럼 보안이 필요 없는 곳에는 xxHash, MurmurHash3처럼 **빠른 비암호화 해시** 를 쓴다.
- 해시는 암호화가 아니다. 데이터를 숨겨야 한다면 별도로 암호화해야 한다.

## 해시 함수의 성질

- 모든 해시 함수의 공통 성질
  - 입력이 같으면 해시 값도 항상 같다.
  - 입력 길이와 상관없이 해시 값의 길이는 일정하다.
  - 입력이 조금만 달라도 해시 값은 완전히 달라진다(눈사태 효과).
- **암호학적 해시 함수** 는 다음 공격도 불가능해야 한다.

| 성질 | 의미 | 깨지면 생기는 일 |
| --- | --- | --- |
| 역상 저항성(제1 역상) | 해시 값만 보고 원래 입력을 찾을 수 없다 | 저장된 해시에서 원문 복원 |
| 제2 역상 저항성 | 주어진 입력과 **같은 해시 값을 내는 다른 입력** 을 찾을 수 없다 | 정상 파일을 같은 해시의 악성 파일로 바꿔치기 |
| 충돌 저항성 | 같은 해시 값을 내는 **아무 입력 쌍** 도 찾을 수 없다 | 위조 인증서, 위조 서명 |

> **참고** "안전한 해시 함수"는 "현재까지 알려진 공격으로는 안전하다"는 뜻이다. MD5와 SHA-1도 처음에는 안전하다고 여겨졌다. 알고리즘을 쉽게 바꿀 수 있도록 설계해 두는 것이 좋다.

## 해시 함수 종류

| 함수 | 해시 길이 | 상태 | 용도 |
| --- | --- | --- | --- |
| MD5 | 128비트 | 2004년 충돌 공격 발표. 지금은 일반 PC로 쉽게 충돌을 만든다 | 보안 용도 금지. 단순 체크섬 정도 |
| SHA-1 | 160비트 | 2017년 구글과 CWI가 실제 충돌(SHAttered)을 공개 | 보안 용도 금지. 기존 시스템 호환용 |
| SHA-2(SHA-224/256/384/512) | 224~512비트 | 안전 | **보안 용도의 기본 선택** |
| SHA-3 | 224~512비트 | 안전. SHA-2와 내부 구조가 완전히 다름 | SHA-2 대안 |
| BLAKE2, BLAKE3 | 가변 | 안전하면서 SHA-2보다 빠름 | 파일 무결성, 고성능 해시 |

- 안전한 함수일수록 대체로 해시 값이 길고 계산 비용이 크다. 기가바이트 단위 파일을 다룰 때는 이 차이가 커진다. `hash_performance.py` 로 직접 비교해 볼 수 있다.

## 실사용 예

### 비밀번호 저장

- 비밀번호는 원문이 아니라 해시 값으로 저장한다. 로그인할 때 입력한 비밀번호의 해시 값을 저장된 값과 비교한다.
- **SHA-256 같은 빠른 해시를 그대로 쓰면 안 된다.** GPU 한 대로 초당 수십억 번 계산할 수 있어서, DB가 유출되면 흔한 비밀번호는 금방 찾아낸다.
- 비밀번호 전용 함수는 계산 비용(반복 횟수, 메모리 사용량)을 조절할 수 있어서, 공격자의 시도 속도를 크게 늦춘다.

| 함수 | 특징 | 파이썬 |
| --- | --- | --- |
| **Argon2id** | 2015년 비밀번호 해싱 대회 우승. 메모리도 많이 써서 GPU 공격에 강함. **새 시스템의 1순위** | `argon2-cffi` 패키지 |
| bcrypt | 오래 검증됨. 입력은 72바이트까지만 사용 | `bcrypt` 패키지 |
| scrypt | 메모리를 많이 사용 | `hashlib.scrypt` |
| PBKDF2 | FIPS 인증이 필요할 때. 반복 횟수를 충분히 크게 설정 | `hashlib.pbkdf2_hmac` |

#### 솔트

- **솔트(salt)** 는 비밀번호에 덧붙이는 무작위 값이다. 사용자마다 다른 값을 만들어 해시와 함께 저장한다.
- 솔트가 없으면 생기는 문제
  - 같은 비밀번호를 쓰는 사용자들의 해시 값이 같아진다. 하나만 알아내면 나머지도 모두 알게 된다.
  - 흔한 비밀번호의 해시를 미리 계산해 둔 표(**레인보우 테이블**)로 바로 찾아낼 수 있다.
- 솔트는 비밀이 아니다. 해시 값 옆에 그대로 저장해도 된다. 비밀로 관리할 추가 값이 필요하면 DB 밖(설정 서버 등)에 보관하는 **페퍼(pepper)** 를 쓴다.
- 위 함수들은 솔트 생성과 저장을 알아서 처리한다. 결과 문자열 하나에 알고리즘, 비용, 솔트, 해시 값이 모두 들어 있다.

```python
from argon2 import PasswordHasher  # pip install argon2-cffi

ph = PasswordHasher()
stored = ph.hash("p@ssw0rd")   # $argon2id$v=19$m=65536,t=3,p=4$<솔트>$<해시>
ph.verify(stored, "p@ssw0rd")  # 일치하지 않으면 예외 발생
```

#### 해시는 어디서 만들까

- 클라이언트는 HTTPS로 비밀번호 원문을 보내고, **서버가 받자마자 해시로 바꾼다.**
- 클라이언트에서 해시를 만들어 보내면, 서버 입장에서는 그 해시 값이 곧 비밀번호가 된다. DB가 유출되면 공격자는 저장된 해시 값을 그대로 보내 로그인할 수 있으므로 해시를 쓰는 의미가 사라진다.
- 서버 코드에서는 비밀번호 원문을 로그에 남기지 않고, 원문이 담긴 변수는 가능한 한 빨리 버린다.

> **주의** 해시 값을 비교할 때 `==` 대신 `hmac.compare_digest()` 를 쓰면 비교 시간 차이로 정보가 새는 타이밍 공격을 막을 수 있다. 위 라이브러리들은 내부에서 이미 이렇게 처리한다.

### 데이터 무결성 검증

- 파일을 내려받은 뒤 해시 값을 공개된 값과 비교하면 전송 중 손상이나 변조를 확인할 수 있다. 이때는 SHA-256을 쓴다.
- 메신저나 클라우드 저장소는 업로드된 파일의 해시 값으로 이미 가진 파일인지 확인한다. 같은 파일을 한 번만 저장해 저장 공간을 아낀다.
- 해시 값만으로는 "누가 만들었는지"를 보장할 수 없다. 공격자가 데이터와 해시 값을 함께 바꿀 수 있기 때문이다. 비밀 키를 공유한 사이에서는 **HMAC** 을, 공개적으로 검증해야 한다면 **전자 서명** 을 쓴다([16장](../ch16_https/README.md)).

### 해시 값을 키로 사용

- 해시 테이블(파이썬 `dict`), 캐시 키, 데이터 샤딩처럼 값을 빠르게 나누고 찾는 데 쓴다. 이때는 xxHash, MurmurHash3처럼 빠른 비암호화 해시가 적합하다.
- 해시 값이 길어도 키가 많아지면 충돌 확률이 빠르게 커진다(생일 문제). 충돌이 나면 원래 값을 다시 비교하는 등 **충돌 처리** 를 항상 넣는다.

## 예제 코드

| 파일 | 내용 |
| --- | --- |
| `md5.py` | MD5 해시 값과 길이(16진수 32자) |
| `sha1.py` | SHA-1 해시 값과 길이(16진수 40자) |
| `sha2.py` | SHA-256(64자)과 SHA-512(128자) 비교 |
| `hash_performance.py` | MD5와 SHA-512로 해시 100만 개를 만들어 속도 비교 |
| `verify_password.py` | 솔트를 붙인 SHA-256으로 비밀번호를 저장하고 확인 |

```sh
cd ch07_hash
../.venv/Scripts/python.exe sha2.py
```

> **주의** `verify_password.py` 는 해시와 솔트의 원리를 보여주는 예제다. 모든 사용자에게 고정된 솔트(`"my_salt"`)를 쓰고, 빠른 SHA-256을 사용하므로 실제 서비스에 그대로 쓰면 안 된다. 실무에서는 위의 Argon2id 예시처럼 구현한다.

## 더 알아보기

- [OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html): 알고리즘별 권장 설정값
- 일관된 해싱(consistent hashing): 서버를 추가하거나 빼도 다시 배치해야 하는 키를 최소화하는 샤딩 기법
- 파이썬 `hashlib.md5(usedforsecurity=False)`: 보안 용도가 아님을 명시해, FIPS 모드 환경에서도 MD5를 체크섬 용도로 쓸 수 있다.
