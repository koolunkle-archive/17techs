# 06. 난수

> 난수는 UUID, 토큰, 게임 확률 등 여러 곳에 쓰인다. 용도마다 필요한 성질이 다르다. 빨라야 하는지, 예측할 수 없어야 하는지, 공정하게 느껴져야 하는지에 따라 생성 방법을 고른다.

## 핵심 요약

- 일반 난수 함수(파이썬 `random`)는 **유사 난수** 다. 시드가 같으면 같은 수열이 나오고, 출력 값을 충분히 모으면 다음 값을 예측할 수 있다.
- 토큰, 비밀번호 재설정 링크, OTP, 세션 ID처럼 **보안에 쓰는 값** 은 반드시 **암호학적으로 안전한 난수**(파이썬 `secrets`)로 만든다.
- 시드는 프로그램 시작 시 **한 번만** 설정한다. 테스트처럼 결과를 재현해야 할 때만 고정된 시드를 쓴다.
- 사용자 경험에 직접 영향을 주는 게임 확률은 **셔플 백** 이나 보정 장치로 "공정하게 느껴지도록" 제어한다.

## 유사 난수(PRNG)

- 컴퓨터는 정해진 계산만 할 수 있으므로, **시드(seed)** 라는 초깃값에서 출발해 공식으로 다음 값을 계속 만들어 낸다. 이렇게 만든 수를 **유사 난수** 라고 한다.
- 대부분의 언어는 **메르센 트위스터(MT19937)** 를 쓴다. 주기가 매우 길고(2¹⁹⁹³⁷−1) 분포가 고르며 빠르지만, 암호학적으로는 안전하지 않다.
  - 내부 상태가 32비트 값 624개로 이루어져 있어서, 연속된 출력 624개를 모으면 내부 상태를 복원해 이후 값을 모두 예측할 수 있다.

### 시드 값과 재현성

- 시드가 같으면 항상 같은 수열이 나온다. 이 성질은 테스트, 시뮬레이션, 게임 리플레이처럼 결과를 재현해야 할 때 유용하다.

```python
random.seed(0)                # 시드를 고정하면
print(random.randrange(1, 10)) # 실행할 때마다 같은 값이 나온다
```

- 파이썬의 `random.seed()` 를 인자 없이 호출하면 운영체제가 제공하는 난수(`os.urandom`)로 시드를 정하고, 그럴 수 없을 때만 현재 시각을 쓴다. `random` 모듈은 처음 불러올 때 이렇게 자동으로 시드를 정하므로 직접 호출할 필요는 거의 없다.
- 타임스탬프처럼 예측 가능한 값을 시드로 쓰면, 공격자가 시각 범위를 좁혀 시드를 알아낼 수 있다.

## 예측 가능한 난수를 쓰면 안 되는 곳

### 토큰, 시크릿, OTP, 비밀 URL

- 권한을 증명하는 값이 예측되면 다른 사람의 권한을 도용할 수 있다. 출력값을 모아 내부 상태를 알아내는 작업은 자동화 도구로 충분히 가능하다.

### 게임 아이템과 재화

- 몬스터 보상이나 랜덤 박스는 **드롭 테이블**(획득할 수 있는 아이템과 확률 목록)과 난수로 결과를 정한다. 예를 들어 확률 5% 아이템은 1~100 범위의 난수에서 5 이하가 나와야 얻는다.
- 시드를 고정하거나 예측할 수 있으면, 사용자가 결과를 미리 알고 원하는 아이템만 가져갈 수 있다.

## 암호학적으로 안전한 난수(CSPRNG)

- 운영체제가 하드웨어 이벤트 등에서 모은 **엔트로피** 로 시드를 정하고 계속 갱신하기 때문에, 이전 출력을 모아도 다음 값을 예측할 수 없다.
  - 리눅스는 `/dev/urandom`(`getrandom()`), 윈도우는 `BCryptGenRandom()` 을 사용한다.
- 유사 난수보다 느리지만, 대부분의 용도에서는 차이가 문제 되지 않는다.

```python
import secrets

token = secrets.token_urlsafe(32)   # URL에 넣을 수 있는 토큰
otp = f"{secrets.randbelow(10**6):06d}"  # 6자리 OTP
```

> **주의** `os.urandom(4)` 결과를 `% 10` 처럼 나머지 연산으로 범위를 줄이면 일부 숫자가 더 자주 나오는 편향이 생긴다. 범위가 있는 난수는 `secrets.randbelow()` 나 `secrets.choice()` 를 사용한다.

## 공정한 난수: 셔플 백

- 순수한 난수는 공정하지만 공정하게 **느껴지지는 않는다.** 확률 30%인데 열 번 연속 실패하는 일도 생긴다.
- **셔플 백** 은 가능한 결과를 확률대로 미리 가방에 담고 섞은 뒤 차례로 꺼내는 방식이다. 당첨 3개와 꽝 7개를 넣고 섞으면, 열 번 안에 반드시 세 번 당첨된다. 확률은 지키면서 순서만 무작위로 정한다.
- 결과 종류가 많거나 확률이 아주 낮으면(예: 0.01%) 가방이 지나치게 커진다. 또 사용자마다 가방을 따로 둘지, 모두가 하나를 공유할지도 설계해야 한다.

## 용도별 선택

| 용도 | 권장 방법 | 이유 |
| --- | --- | --- |
| 요청·작업 ID | `uuid.uuid4()` 또는 빠른 유사 난수 | 겹치지 않고 빠르기만 하면 된다 |
| 토큰, OTP, 세션 ID, 솔트 | `secrets` | 예측할 수 없어야 한다 |
| 랜덤 박스 | 안전한 난수 + 확률 공개 + 천장(일정 횟수 후 확정 지급) | 결과가 돈과 직결되고 법적 의무가 있다 |
| 치명타, 카드 뽑기 | 셔플 백, 실패할수록 확률을 높이는 보정 | 체감 공정성이 중요하다 |
| 테스트, 시뮬레이션 | 고정 시드 유사 난수 | 재현할 수 있어야 한다 |

> **참고** 국내에서는 2024년 3월부터 게임산업법에 따라 확률형 아이템의 확률 공개가 의무화되었다. 공개한 확률과 실제 동작이 일치하는지 검증할 수 있도록 난수 로직과 로그를 설계해야 한다.

## 더 알아보기

- 파이썬 `random.SystemRandom` 클래스: `random` 과 같은 사용법으로 운영체제의 안전한 난수를 쓴다.
- 가중치가 있는 무작위 선택: `random.choices(items, weights=...)`
- 하드웨어 난수 생성기(HRNG): 열 잡음 같은 물리 현상을 이용한다. 최신 CPU에는 `RDRAND` 명령이 있다.
