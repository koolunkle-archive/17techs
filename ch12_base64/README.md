# 12. Base64

> Base64는 바이너리 데이터를 64개의 안전한 ASCII 문자로 바꾸는 인코딩이다. JSON, XML, URL, 이메일처럼 텍스트만 다룰 수 있는 곳에 이미지나 파일 같은 바이너리를 담을 때 쓴다.

## 핵심 요약

- 바이너리 3바이트(24비트)를 6비트씩 나눠 문자 4개로 바꾼다. 그래서 크기가 약 **33%(4/3배)** 늘어난다.
- 길이가 3의 배수가 아니면 끝에 패딩 `=` 또는 `==` 를 붙인다.
- URL이나 파일 이름에 넣을 때는 `+`, `/` 대신 `-`, `_` 를 쓰는 **URL-safe Base64(base64url)** 를 쓴다.
- Base64는 **암호화가 아니다.** 누구나 바로 디코딩할 수 있다.
- 큰 파일은 Base64로 바꿔 JSON에 넣지 말고 HTTP `multipart/form-data` 나 별도 파일 저장소를 쓴다.

## 왜 필요한가

- JSON은 UTF-8 문자열만 담을 수 있다([8장](../ch08_json/README.md)). 이미지 같은 바이너리를 그대로 넣으면 UTF-8로 해석할 수 없는 바이트가 섞여 오류가 난다.
- Base64로 바꾸면 결과가 `A-Z`, `a-z`, `0-9`, `+`, `/` 로만 이루어진다. 어떤 텍스트 형식에 넣어도 깨지지 않고, 따옴표·괄호 같은 예약 문자와도 겹치지 않는다.
- 쓰이는 곳: 이메일 첨부 파일(MIME), JSON 안의 바이너리 필드, HTML·CSS의 `data:` URI, HTTP Basic 인증 헤더, JWT 토큰, 인증서(PEM) 파일

## 인코딩 원리

1. 입력 바이트를 비트로 나열한다.
2. 3바이트(24비트)씩 끊는다.
3. 24비트를 6비트씩 4조각으로 나눈다. 6비트는 0~63의 값이다.
4. 각 값을 표에 따라 문자로 바꾼다.

| 값 | 0~25 | 26~51 | 52~61 | 62 | 63 |
| --- | --- | --- | --- | --- | --- |
| 문자 | `A`~`Z` | `a`~`z` | `0`~`9` | `+` | `/` |

```text
입력:  M        a        n
비트:  01001101 01100001 01101110
6비트: 010011 010110 000101 101110
값:    19     22     5      46
출력:  T      W      F      u        → "TWFu"
```

### 패딩

- 입력이 3바이트로 나누어떨어지지 않으면 0 비트를 채워 마지막 조각을 만들고, 모자란 바이트 수만큼 `=` 를 붙인다.
  - 1바이트 남음 → 문자 2개 + `==`
  - 2바이트 남음 → 문자 3개 + `=`
- 16바이트인 UUID를 인코딩하면 `16 = 3 × 5 + 1` 이라 항상 `==` 로 끝나는 24글자가 된다(`base64_with_uuid.py`).
- 패딩이 있으면 결과 길이가 항상 4의 배수가 된다. 스트림으로 데이터를 받을 때 "여기까지가 한 덩어리"라고 판단할 수 있다.
- 반대로 JSON 필드나 HTTP 본문처럼 데이터 길이를 이미 아는 곳에서는 패딩이 없어도 디코딩할 수 있다. 그래서 URL·JWT에서는 패딩을 생략하기도 한다.

## 디코딩

- 인코딩의 역순이다. 문자를 6비트 값으로 되돌려 이어 붙이고 8비트씩 끊어 바이트로 만든다. 패딩만큼 생긴 끝부분의 0 비트는 버린다.
- 디코딩한 결과는 그냥 바이트다. 이미지인지 압축 파일인지는 결과만 봐서는 알 수 없으므로, 종류를 함께 보낸다.

```json
{
    "type": "image/png",
    "data": "iVBORw0KGgoAAAANSUhEUgAA..."
}
```

## 파이썬에서 사용

```python
import base64

encoded = base64.b64encode(raw_bytes)            # bytes → Base64 bytes
text = encoded.decode("ascii")                   # JSON에 넣을 문자열
raw = base64.b64decode(text)                     # 다시 원본 bytes로

url_safe = base64.urlsafe_b64encode(raw_bytes)   # + / 대신 - _ 사용
```

- 표준 라이브러리 `base64` 는 C로 구현되어 빠르다. 직접 구현하지 말고 언어가 제공하는 라이브러리를 쓴다.

## URL-safe Base64

- 표준 Base64의 `+` 와 `/` 는 URL에서 특별한 의미가 있고, `=` 는 쿼리 문자열의 구분자다.
- **base64url**(RFC 4648)은 두 문자를 바꾸고, 길이를 알 수 있는 URL에서는 보통 패딩을 생략한다.

| 표준 Base64 | base64url |
| --- | --- |
| `+` | `-` |
| `/` | `_` |
| `=` 패딩 | 보통 생략(필요하면 `%3D` 로 퍼센트 인코딩) |

- 파이썬 `urlsafe_b64encode()` 는 패딩을 남기므로, 생략하려면 `.rstrip(b"=")` 로 지운다. 디코딩할 때는 길이가 4의 배수가 되도록 `=` 를 다시 붙인다.

## 주의할 점

- **크기**: 33%가 늘어나고, JSON 안의 긴 문자열은 파싱과 메모리 비용도 크다. 수 MB 이상의 파일은 `multipart/form-data` 로 업로드하거나, 파일 저장소(S3 등)에 올리고 URL만 주고받는다.
- **보안**: Base64는 인코딩일 뿐이다. 비밀번호나 토큰을 Base64로 바꿨다고 안전해지지 않는다(HTTP Basic 인증이 반드시 HTTPS와 함께 쓰여야 하는 이유).
- **스트림**: 실시간 영상처럼 끝을 알 수 없는 데이터를 Base64로 주고받는 일은 드물다. 이런 경우에는 RTMP, HLS 같은 전용 프로토콜을 쓴다.

## 예제 코드

| 파일 | 내용 |
| --- | --- |
| `my_base64.py` | `bitstring` 으로 Base64 인코딩·디코딩을 직접 구현하고 결과를 `message2.json` 으로 저장 |
| `base64_with_uuid.py` | UUID 16바이트를 Base64로 인코딩하고 다시 복원 |

```sh
cd ch12_base64
../.venv/Scripts/python.exe base64_with_uuid.py
```

> **참고** `my_base64.py` 는 8장의 `message1.json` 을 인코딩한 뒤 다시 디코딩해 `message2.json` 으로 저장한다. 두 파일이 같으면 구현이 맞다. 디코딩할 때 패딩 때문에 채웠던 0 비트(8비트 미만)를 버리지 않으면 끝에 불필요한 바이트가 붙는다.

## 더 알아보기

- **Base32, Base58**: 대소문자 구분이 어렵거나 헷갈리는 문자(`0`/`O`, `l`/`I`)를 피해야 할 때 쓴다(OTP 시크릿, 비트코인 주소).
- **MIME Base64**: 이메일에서는 76자마다 줄바꿈을 넣는다. 파이썬 `base64.encodebytes()` 가 이 형식이다.
- **HTTP multipart**: 파일과 폼 필드를 바이너리 그대로 함께 보내는 방법
