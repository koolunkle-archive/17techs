# 08. JSON

> JSON은 키와 값으로 데이터를 표현하는 텍스트 형식이다. 사람이 읽기 쉽고 거의 모든 언어가 지원해서, API와 설정, 데이터 저장에 가장 많이 쓴다.

## 핵심 요약

- 특별한 이유가 없다면 메시지 형식은 **JSON으로 시작한다.** 사람이 읽고 디버깅하기 쉽고, 거의 모든 언어와 도구가 지원한다.
- 규칙: **UTF-8**, BOM 금지, 주석 없음, 키는 큰따옴표로 감싼 문자열, 마지막 항목 뒤에 쉼표 금지.
- 외부에서 들어온 JSON은 **파싱 실패, 키 누락, 타입 오류** 를 모두 가정하고 검증한다.
- 텍스트라서 크기가 크고, 형식이 바뀌어도 컴파일 단계에서 알 수 없다. 메시지에 **버전** 을 두거나 **스키마**(JSON Schema, OpenAPI)로 형식을 관리한다.

## JSON 구조

```json
{
    "number": 12345,
    "pi": 3.14,
    "str": "문자열 값",
    "null_key": null,
    "object": { "str2": "문자열 값2", "object2": { "number2": 12345 } },
    "num_array": [1, 2, 3, 4, 5],
    "str_array": ["one", "two", "three", "four", "five"]
}
```

| 값 타입 | 예 | 참고 |
| --- | --- | --- |
| 숫자 | `12345`, `3.14` | 정수와 실수를 구분하지 않는다 |
| 문자열 | `"문자열 값"` | 반드시 큰따옴표 |
| 불리언 | `true`, `false` | 소문자 |
| null | `null` | 값 없음 |
| 객체 | `{ "key": 값 }` | 키는 문자열만 가능 |
| 배열 | `[1, "two", {}]` | 여러 타입을 섞을 수 있다 |

- 최상위 값은 객체나 배열이 일반적이다. 실무에서는 **객체** 로 시작하는 것이 좋다. 나중에 `version`, `next_cursor` 같은 필드를 추가해도 기존 클라이언트가 깨지지 않기 때문이다.
- 키에 한글을 쓸 수는 있지만, 코드의 변수 이름과 바로 대응시킬 수 있도록 영문(ASCII)을 쓴다.

### 문자 이스케이프

- 문자열 안에 큰따옴표, 역슬래시, 줄바꿈 같은 문자를 넣을 때는 역슬래시로 **이스케이프** 한다.

```json
{ "str": "큰따옴표는 \"이렇게\" 표현한다.\n두 번째 줄\t탭" }
```

### 문자 인코딩과 주석

- JSON은 시스템 간에 주고받을 때 **UTF-8** 을 써야 하며 BOM을 붙이지 않는다([1장](../ch01_text_encoding/README.md)). UTF-16을 기본으로 쓰는 윈도우나 자바, 또는 EUC-KR 환경에서 파일을 만들 때 특히 주의한다.
- JSON 표준에는 주석이 없다. 주석을 허용하는 라이브러리(JSONC, JSON5)도 있지만, 다른 시스템이 읽지 못할 수 있다. 주석이 필요한 설정 파일에는 YAML을 고려한다([9장](../ch09_yaml/README.md)).

## 직렬화와 역직렬화

| 용어 | 방향 | 파이썬 |
| --- | --- | --- |
| **직렬화**(serialization) | 객체(`dict`, `list`) → JSON 문자열 | `json.dumps()`, `json.dump()` |
| **역직렬화**(deserialization) | JSON 문자열 → 객체 | `json.loads()`, `json.load()` |

```python
with open("message2.json", "w", encoding="utf-8") as file:
    json.dump(message2, file, ensure_ascii=False, indent=2)
```

- `ensure_ascii=False`: 한글을 `\uXXXX` 로 바꾸지 않고 그대로 쓴다.
- `indent=2`: 들여쓰기로 읽기 쉽게 만든다. 네트워크로 보낼 때는 생략해 크기를 줄인다.
- 파일을 열 때는 항상 `encoding="utf-8"` 을 명시한다.

## JSON을 읽을 때 주의할 점

- 외부 파일이나 HTTP 요청의 JSON은 잘못된 형식일 수 있다고 가정한다. 형식이 틀리면 그 자리에서 처리를 멈추고 오류를 응답한다.

### 출처에 따라 다르게 처리한다

| 출처 | 처리 방법 |
| --- | --- |
| 외부(사용자 요청, 업로드 파일, 외부 API) | 파싱 오류를 잡고, **필요한 키가 있는지와 값의 타입·범위** 를 모두 검사한다. 키가 없을 때 쓸 기본값을 정한다 |
| 내부(우리 서버끼리 통신, 우리가 만든 파일) | 형식이 미리 합의되어 있으므로 키가 없으면 버그로 보고 예외(`KeyError`)로 처리한다 |

```python
try:
    data = json.loads(body)
except json.JSONDecodeError as e:
    return f"잘못된 JSON 형식입니다: {e}", 400

title = data.get("title")
if not isinstance(title, str) or not title:
    return "title은 비어 있지 않은 문자열이어야 합니다.", 400
```

> **주의** 파이썬의 `assert` 는 `python -O` 로 실행하면 제거된다. 외부 입력 검증에는 `assert` 를 쓰지 않는다. 검증할 필드가 많다면 `pydantic` 이나 `jsonschema` 같은 라이브러리를 쓴다.

- 객체 안 키의 순서나 배열 요소의 정렬 순서를 가정하지 않는다. 라이브러리나 중간 시스템에 따라 순서가 바뀔 수 있다.
- 숫자 정밀도: 자바스크립트는 2⁵³보다 큰 정수를 정확히 표현하지 못한다. 64비트 ID나 금액은 **문자열** 로 주고받는 것이 안전하다.

## JSON을 만들 때 주의할 점

### 빈 값을 표현하는 규칙을 정한다

- `null` 만 보고는 원래 어떤 타입의 값인지 알 수 없다. 필드의 타입이 정해져 있다면 타입에 맞는 빈 값을 쓰는 것이 다루기 쉽다.

| 타입 | 빈 값 |
| --- | --- |
| 숫자 | `0` |
| 문자열 | `""` |
| 객체 | `{}` |
| 배열 | `[]` |

- 다만 "값이 0이다"와 "값이 없다(모른다)"를 구분해야 하는 필드라면 `null` 이 맞다. 중요한 것은 필드마다 규칙을 정하고 문서화하는 것이다.

### 키 이름 규칙을 통일한다

- JSON 자체에는 키 이름 규칙이 없다. 파이썬과 PHP는 `snake_case`, 자바와 자바스크립트는 `camelCase` 를 주로 쓰며, 구글 JSON 스타일 가이드는 `camelCase` 를 권장한다.
- 어느 쪽이든 **한 서비스 안에서는 하나로 통일한다.** 섞어 쓰면 클라이언트 코드가 지저분해지고 실수가 늘어난다.

## JSON의 한계와 대응

### 크기와 처리 비용

- 키 이름과 따옴표가 메시지마다 반복되어, 같은 데이터를 바이너리 형식(프로토콜 버퍼)보다 크게 표현한다([11장](../ch11_protocol_buffer/README.md)).
- 압축하면 크기는 많이 줄지만 CPU를 더 쓴다([13장](../ch13_zlib/README.md)). 메시지가 많은 서버라면 적용 전에 부하 테스트를 한다.

### 형식 변경을 알아채기 어렵다

- 서버가 필드 이름이나 타입을 바꿔도 클라이언트는 실행해 보기 전까지 모른다. 팀과 서비스가 커질수록 누락이 생긴다.
- 대응 방법
  - **메시지 버전**: `{"version": 2, "data": {...}}` 처럼 형식 버전을 명시한다.
  - **API 버전**: `https://example.com/v1/posts` 처럼 URL에 버전을 넣는다([15장](../ch15_restful_api/README.md)).
  - **스키마와 코드 생성**: JSON Schema나 OpenAPI로 형식을 정의하고 검증 코드나 클라이언트 코드를 생성한다. 프로토콜 버퍼처럼 스키마로 인터페이스 코드를 만들면 형식이 바뀌었을 때 컴파일 단계에서 알 수 있다.
  - **호환성 규칙**: 필드는 추가만 하고, 이름 변경이나 삭제는 새 버전에서 한다.

## 더 알아보기

- **JSON Lines(NDJSON)**: 한 줄에 JSON 하나씩 쓰는 형식. 로그나 대용량 데이터를 한 줄씩 처리할 때 쓴다.
- **BSON**: MongoDB가 쓰는 바이너리 JSON. 표준이 아니므로 다른 시스템과 바이너리를 주고받을 때는 Base64를 쓴다([12장](../ch12_base64/README.md)).
- **JSON Patch / JSON Merge Patch**: JSON 문서의 일부만 바꾸는 표준 형식. HTTP `PATCH` 요청에 쓴다.
